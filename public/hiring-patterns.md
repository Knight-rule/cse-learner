## Google — SDE Roles

### 1. Hiring Process Overview

| Stage | Format | Duration |
|-------|--------|----------|
| Resume Screen | Recruiter review | 1-2 weeks |
| Recruiter Screen | Phone call, behavioral + light technical | 30 min |
| Phone Screen | Live coding, 1 problem + behavioral | 45 min |
| Onsite Loop | 4-5 rounds (virtual, single day) | 4 hrs total |
| Hiring Committee | Asynchronous packet review | 1-2 weeks |
| Team Match | Conversations with hiring managers | 2-6 weeks |
| Offer | Compensation committee review | 1 week |

**Total timeline:** 6-10 weeks from first contact to offer

**2026 Changes:**
- Gemini-paired AI coding round at L4+ (one of two coding rounds allows Gemini)
- Googleyness 2.0 rubric with 4 structured axes
- System design now appears at L4 (scaled-down)
- Loop compressed to 4 hours single day

### 2. Skills & Topics Tested

**Core Technical:**
- Languages: C++, Java, Python, Go (no preference, pick one you're fluent in)
- DSA: Arrays, strings, trees, graphs (BFS/DFS, topological sort), DP, binary search on answer, intervals, backtracking
- System Design (L4+): Distributed systems, caching, load balancing, database sharding, API design

**CS Fundamentals:**
- Time/space complexity analysis (must state for every solution)
- Graph algorithms, tree traversals, dynamic programming
- Concurrency basics

**Behavioral (Googleyness):**
- Collaboration and conflict resolution
- Comfort with ambiguity
- Intellectual humility ("I don't know, here's how I'd find out")
- User-first thinking
- Learning mindset

**2026 Addition:** AI fluency — prompt engineering, output validation, debugging with AI tools

### 3. Preparation Roadmap

**Week 1-2: Foundations**
- Master arrays, strings, hashing, two pointers, sliding window
- Solve 30-40 LeetCode mediums
- Resources: LeetCode, NeetCode.io, Cracking the Coding Interview

**Week 3-4: Core DSA**
- Trees (DFS, BFS, LCA), graphs (BFS, DFS, topological sort, Dijkstra)
- DP (knapsack, LCS, LIS, coin change)
- Solve 40-60 more problems

**Week 5: System Design**
- Learn RESHADED framework
- Practice 3 designs: URL shortener, news feed, chat system
- Resources: Designing Data-Intensive Applications, System Design Interview (Alex Xu)

**Week 6: Googleyness Prep**
- Prepare 8 STAR stories cross-tagged to 4 Googleyness axes
- Practice with a partner
- Resources: "Googleyness" blog posts, mock interviews

**Week 7: AI-Assisted Coding Practice**
- Practice reading unfamiliar code, debugging, optimizing with AI tools
- Read open-source codebases, describe what they do before running

**Week 8: Mock Interviews**
- 2-3 full loop mocks on interviewing.io
- Taper: 1 mock per day, sleep optimization

**Key Resources:**
- LeetCode (Google-tagged problems)
- NeetCode.io (pattern-based learning)
- Designing Data-Intensive Applications (Kleppmann)
- interviewing.io (mock interviews)
- Google AI Coding practice (for Gemini round)

### 4. Application Tips

**Resume:**
- Quantify impact ("reduced latency by 40%", "served 10M users")
- List specific technologies and frameworks
- GitHub links to meaningful projects (not tutorials)

**Common Questions:**
- "Tell me about a time you dealt with ambiguity"
- "Describe a disagreement and how you handled it"
- "Tell me about a project you drove yourself"
- "Describe a time you failed and what you learned"

**Red Flags:**
- Silent coding — narrate your thought process always
- Stopping at brute force — must optimize
- Ignoring interviewer hints — use them gracefully
- Inconsistent performance across rounds (HC weights consistency)

### 5. Leveling Guide

| Level | Title | System Design | Behavioral Weight |
|-------|-------|---------------|-------------------|
| L3 | SWE I (New Grad) | Rare | Light |
| L4 | SWE II | Scaled-down at phone screen | Moderate |
| L5 | Senior SWE | Mandatory, full round | Heavy |
| L6 | Staff SWE | Two rounds | Leadership focus |

## Microsoft — SDE Roles

### 1. Hiring Process Overview

| Stage | Format | Duration |
|-------|--------|----------|
| Resume Screen | Recruiter review | 1-2 weeks |
| Recruiter Screen | Phone call | 30-45 min |
| Online Assessment | 2-3 DSA problems on Codility | 60-90 min |
| Onsite Loop | 4-5 rounds via Teams | 60 min each |
| As-Appropriate (AA) | Senior interviewer, holistic | 45-60 min |
| Offer | Within 1 week of onsite | - |

**Total timeline:** 4-8 weeks from application to offer

**2026 Changes:**
- IDC reduced from 5 to 4 rounds for new grads
- Distributed systems now table stakes
- More AI/ML questions in coding rounds
- Cloud-aware system design (Azure-specific trade-offs)

### 2. Skills & Topics Tested

**Core Technical:**
- Languages: C++, C#, Java, Python
- DSA: Trees and graphs dominate; arrays, strings, hashing, greedy, DP
- Difficulty: Mostly LeetCode medium
- System Design (L61+): URL shortener, notification system, collaborative editing

**CS Fundamentals:**
- OOPs concepts (with real-world examples)
- DBMS: Normalization (up to 3NF), SQL queries (second highest salary, self-joins)
- OS: Process scheduling, memory management
- Computer Networks: TCP/IP, HTTP, DNS

**Behavioral:**
- Growth mindset (Satya Nadella's core criterion)
- Learning from failure
- Collaboration and feedback handling
- Customer impact thinking

### 3. Preparation Roadmap

**Week 1-2: OA Prep**
- Arrays, strings, hashing, greedy
- Solve 30-40 problems
- Practice on Codility (platform-specific)
- Resources: GeeksforGeeks, LeetCode (Microsoft-tagged)

**Week 3-4: Core DSA**
- Trees (path sum, LCA, traversal), graphs (BFS, DFS, connected components)
- Linked lists, heap/priority queue, DP basics
- Solve 40-60 problems total

**Week 5: System Design**
- Basic LLD: class modeling, SOLID principles
- Simple HLD: URL shortener, notification service
- Azure-specific: Blob Storage vs S3, multi-region failover

**Week 6: Behavioral + AA Prep**
- Prepare 6-8 STAR stories showing growth mindset
- Practice the AA round as a full interview (not wind-down)

**Week 7-8: Mocks**
- Full loop mocks
- Narrate approach before coding every time

**Key Resources:**
- LeetCode (Microsoft-tagged)
- Codility (OA practice)
- Growth Mindset by Carol Dweck (cultural context)
- Azure documentation (for system design)

### 4. Application Tips

**Resume:**
- Emphasize growth and learning
- Mention specific Azure/cloud experience if applicable
- Show progression and impact

**Common Questions:**
- "Tell me about a time you failed and what you learned"
- "How do you handle feedback you disagree with?"
- "Describe a project where you had to learn something new quickly"

**Red Flags:**
- Silent coding — narrate before typing
- Not mentioning Azure in system design (be cloud-aware)
- Treating AA round as a formality (it's a real interview)
- Poor communication clarity

## Amazon — SDE Roles

### 1. Hiring Process Overview

| Stage | Format | Duration |
|-------|--------|----------|
| Resume Screen | Recruiter review | 1-2 weeks |
| Online Assessment | 2 coding problems + system design scenario + work style survey | 90 min + 20 min |
| Phone Screen | 1 coding problem + behavioral | 45-60 min |
| Virtual Onsite Loop | 4-5 rounds | 45-60 min each |
| Bar Raiser | Separate round, veto power | 60 min |
| Debrief | Panel alignment | 60-90 min |
| Offer | After debrief | - |

**Total timeline:** 4-8 weeks from OA to offer

**2026 Changes:**
- Behavioral questions in EVERY round (including technical)
- Bar Raiser rubric tightened around Customer Obsession + Ownership
- AI literacy question in every loop
- Round 2 became two-problem coding (was single until 2024)

### 2. Skills & Topics Tested

**Core Technical:**
- Languages: Java, Python, C++, JavaScript
- DSA: Graphs (BFS/DFS, DSU), DP, sliding window, binary search, trees
- System Design (SDE II+): Amazon-scale scenarios (warehouse, shopping cart, ranking)
- Low-Level Design (SDE I): Parking lot, vending machine, elevator

**Leadership Principles (16 total):**
- Customer Obsession (most probed)
- Ownership (most probed)
- Dive Deep
- Bias for Action
- Earn Trust
- Deliver Results
- Invent and Simplify
- Are Right A Lot
- Learn and Be Curious
- Hire and Develop the Best
- Insist on the Highest Standards
- Think Big
- Bias for Action
- Frugality
- Strive to be Earth's Best Employer
- Success and Scale Bring Broad Responsibility

**AI Literacy (2026):**
- Specific use case where you used AI tools
- Specific case where you chose NOT to use AI (and why)
- Verification habits for AI output
- Limitations you've encountered

### 3. Preparation Roadmap

**Week 1-2: DSA Foundations**
- Master arrays, strings, hashing, two pointers
- Start graphs (BFS, DFS, DSU)
- Solve 30-40 problems
- Resources: LeetCode (Amazon-tagged), NeetCode

**Week 3-4: DSA Depth + System Design**
- DP (knapsack, LCS, LIS), binary search on answer
- System Design: Read DDIA chapters 1-7
- Practice: Design warehouse management, shopping cart at scale

**Week 5-6: Leadership Principles**
- Prepare 8 distinct STAR stories
- Tag each story to 2-4 LPs (cover all 16)
- Have 60-second, 3-minute, and 5-minute versions
- Practice deep follow-ups: "What exactly did you do?"

**Week 7: Bar Raiser Prep**
- This is the hardest round — treat it as such
- Deep dive on Customer Obsession + Ownership stories
- Prepare specific questions for the Bar Raiser

**Week 8: Mocks**
- Full loop mocks with coding + behavioral switching
- Practice the AI literacy answer

**Key Resources:**
- Leadership Principles page (amazon.jobs)
- STAR method templates
- LeetCode (Amazon-tagged, medium-hard)
- DDIA (Chapters 1-7 for system design)

### 4. Application Tips

**Resume:**
- Quantify everything ("increased throughput by 3x", "reduced costs by $50K")
- Show customer impact
- Mention specific AWS technologies if applicable

**Common Questions:**
- "Tell me about a time you made a decision without complete data" (Bias for Action)
- "Describe a time you disagreed with a decision" (Have Backbone, Disagree and Commit)
- "Tell me about a time you went above and beyond for a customer" (Customer Obsession)
- "How do you use AI tools in your workflow?"

**Red Flags:**
- Weak Customer Obsession or Ownership stories (Bar Raiser veto trigger)
- Generic STAR stories without metrics
- Not preparing distinct stories (same story for different LPs)
- Ignoring the AI literacy question

### 5. Bar Raiser Deep Dive

The Bar Raiser is:
- From a different team than your hiring manager
- Trained to maintain Amazon's hiring bar
- Has veto power that cannot be overridden
- Probes Customer Obsession and Ownership most aggressively

**What they grade:**
- Would this person raise the Amazon-wide bar at this level?
- Are the LP stories real and specific?
- Does the candidate show genuine customer focus?
- Would you want this person on your team?

## Meta (Facebook) — SWE Roles

### 1. Hiring Process Overview

| Stage | Format | Duration |
|-------|--------|----------|
| Recruiter Screen | Phone call | 30 min |
| Online Assessment | CodeSignal, proctored | 90 min |
| Technical Phone Screen | 2 LeetCode problems | 45 min |
| Culture Fit Questionnaire | Async multiple choice | 20-30 min |
| Virtual Onsite Loop | 5 rounds (E4/E5) | 45 min each |
| Offer | After hiring committee | - |

**Total timeline:** 2-3 months (candidates can control pacing)

**2026 Changes:**
- Online Assessment now mandatory (CodeSignal)
- AI-enabled coding round (one of two coding rounds)
- Behavioral round can downlevel E5→E4
- E6+ gets only one AI-assisted coding round
- Code execution turned OFF in CoderPad

### 2. Skills & Topics Tested

**Core Technical:**
- Languages: Python, C++, Java, JavaScript
- DSA: 2 problems per coding round (double typical), medium-hard difficulty
- System Design: Social graph scale (News Feed, Instagram Stories, Messenger)
- Product Design: User-facing product architecture

**Coding Patterns:**
- Arrays, strings, hash maps
- Trees (DFS, BFS, level-order)
- Graphs (BFS, DFS, topological sort)
- Dynamic programming
- Binary search
- Sliding window

**System Design:**
- Fanout on write vs read
- CDN for media distribution
- Caching with Redis
- Push vs pull for celebrities
- WebSocket connections
- Graph databases (TAO)

**Behavioral:**
- Cross-team impact and leadership
- Ambiguity navigation
- Conflict resolution
- User empathy

### 3. Preparation Roadmap

**Week 1-2: DSA Intensity**
- Solve 2 problems per session (Meta style)
- Focus on arrays, strings, trees, graphs
- Practice without code execution (dry-run)
- Resources: LeetCode (Meta-tagged), NeetCode

**Week 3-4: System Design**
- Design News Feed, Instagram Stories, Messenger
- Practice capacity estimates with real numbers
- Focus on social graph patterns
- Resources: System Design Interview (Alex Xu), Hello Interview

**Week 5: AI-Enabled Coding Practice**
- Practice multi-part problems with AI assistance
- Learn to validate AI output critically
- Practice prompt engineering for coding

**Week 6: Behavioral**
- Prepare 6-8 stories about cross-team impact
- Practice quantifying your impact
- Resources: Hello Interview behavioral guide

**Week 7-8: Full Loop Mocks**
- 5-round mock sessions
- Practice pacing (2 problems per coding round)

**Key Resources:**
- LeetCode (Meta-tagged)
- Hello Interview (Meta-specific guides)
- System Design Interview (Alex Xu)
- Excalidraw (for design round practice)

### 4. Application Tips

**Resume:**
- Show scale ("built systems serving 1B+ users")
- Mention specific Meta technologies if familiar (React, GraphQL, TAO)
- Highlight cross-team collaborations

**Common Questions:**
- "Tell me about a time you had to influence without authority"
- "Describe a project where you had to make trade-offs"
- "How do you prioritize when everything is urgent?"

**Red Flags:**
- Only solving 1 problem in a coding round (expect 2)
- Not dry-running code (execution is OFF)
- Generic system design without real numbers
- Not using AI in the AI-enabled round (negative signal)

## Apple — SDE Roles

### 1. Hiring Process Overview

| Stage | Format | Duration |
|-------|--------|----------|
| Recruiter Screen | Phone call | 15-30 min |
| Hiring Manager Screen | Team fit discussion | 30-45 min |
| Technical Phone Screen | CoderPad, 1-2 problems | 45-60 min |
| Onsite Loop | 4-6 rounds | 45-60 min each |
| Panel Debrief | Internal discussion | - |
| Offer | After leveling | - |

**Total timeline:** 4-8 weeks (can extend to 3-4 months)

**Key Differences:**
- Team-owned loop (no central question bank)
- Questions map to team's real stack
- No AI-assisted coding (candidates report tools blocked)
- Mobile-first system design
- Code craftsmanship weighted heavily

### 2. Skills & Topics Tested

**Core Technical:**
- Languages: Swift (iOS/macOS), C/C++ (systems), Python, Java
- DSA: Medium difficulty, but high code quality bar
- Concurrency: Thread-safe data structures, GCD, async/await
- System Design: On-device first, offline-first, privacy constraints

**Platform-Specific:**
- iOS: ARC, value vs reference semantics, SwiftUI, Core Data
- macOS: AppKit, memory management
- Systems: C/C++, memory, OS internals
- ML: CoreML, on-device inference

**Behavioral:**
- "Why Apple?" (carries real weight)
- Ownership with minimal direction
- Quality under pressure
- Cross-functional work (design, hardware, QA)
- User empathy

### 3. Preparation Roadmap

**Week 1-2: DSA + Code Quality**
- Arrays, strings, trees, graphs, binary search
- Practice clean code: proper naming, edge cases
- Solve 30-40 problems
- Resources: LeetCode, Apple-tagged problems

**Week 3-4: Concurrency + System Design**
- Thread-safe queue, producer-consumer
- Mobile-first design: offline sync, on-device storage
- Privacy constraints in architecture
- Resources: iOS/macOS documentation, DDIA

**Week 5-6: Platform-Specific + Behavioral**
- Swift: ARC, value types, protocol-oriented design
- Prepare "Why Apple?" answer (specific, not generic)
- 6-8 STAR stories about ownership and quality

**Week 7-8: Mocks + Stamina**
- Back-to-back mock rounds (onsite stamina)
- Practice 60-minute coding sessions
- Domain-specific prep for target team

**Key Resources:**
- Swift documentation (developer.apple.com)
- iOS/macOS Human Interface Guidelines
- LeetCode (concurrency problems)
- WWDC videos (understand Apple's philosophy)

### 4. Application Tips

**Resume:**
- Show craftsmanship: clean code, attention to detail
- Mention Apple technologies if applicable (Swift, CoreML, SwiftUI)
- Highlight on-device/mobile experience

**Common Questions:**
- "Why Apple specifically?" (be genuine, mention products you use)
- "Tell me about a time you shipped quality under pressure"
- "How do you collaborate with design and hardware teams?"

**Red Flags:**
- Generic "Why Apple?" answers about prestige
- Not thinking about offline/privacy in system design
- Poor code naming (i, j, tmp for non-obvious things)
- Not handling edge cases proactively

## TCS — System Engineer / IT Analyst

### 1. Hiring Process Overview

| Stage | Format | Duration |
|-------|--------|----------|
| TCS NQT Exam | Online, proctored, 190 min | 1 day |
| Technical Interview | 20-40 min | 1 round |
| Managerial Interview | 15-30 min | 1 round |
| HR Interview | 10-15 min | 1 round |
| Offer | Based on NQT score + interview | - |

**Total timeline:** 4-8 weeks from test to offer

**Hiring Categories:**
| Category | CTC (UG) | CTC (PG) | Requirements |
|----------|----------|----------|--------------|
| Prime | ₹9-11 LPA | ₹11.5-12 LPA | Top NQT + Advanced coding |
| Digital | ₹7-7.3 LPA | ₹7.3-7.6 LPA | High NQT + Advanced section |
| Ninja | ₹3.36 LPA | ₹3.53 LPA | Base NQT cutoff |

**NQT Exam Structure:**
| Section | Duration | Focus |
|---------|----------|-------|
| Part A: Foundation | 75 min | Numerical, Verbal, Reasoning |
| Part B: Advanced | 115 min | Advanced Quant + Advanced Coding |

### 2. Skills & Topics Tested

**NQT Coding:**
- Arrays, strings, sorting (top 3 topics)
- Basic recursion, HashMap operations
- Skip graphs and DP for base test
- Languages: C, C++, Java, Python

**Technical Interview:**
- OOPs (4 pillars with real-world examples)
- DBMS: Normalization (up to 3NF)
- SQL: Second highest salary, joins
- Project explanation (2 min max)

**Managerial:**
- "Why TCS?" (mention specific projects/tech)
- Willingness to relocate
- Service agreement acceptance

**HR:**
- Communication skills
- Location flexibility
- Salary expectations

### 3. Preparation Roadmap

**Week 1: Aptitude + Verbal**
- IndiaBix, PrepInsta for quantitative and reasoning
- 2 hours/day practice
- Resources: RS Aggarwal, IndiaBIX

**Week 2: Core CS**
- OOPs, DBMS, SQL
- Write actual queries
- Explain concepts to a friend

**Week 3: Coding Practice**
- 30-40 easy/medium problems
- Arrays, strings, sorting focus
- Practice on HackerRank

**Week 4: Interview Prep**
- 2-3 mock interviews
- Prepare "Why TCS" and project walkthrough
- Practice essay writing

**Key Resources:**
- TCS NQT previous papers
- IndiaBIX (aptitude)
- PrepInsta (TCS-specific)
- HackerRank (coding practice)

### 4. Application Tips

**Resume:**
- Keep it 1 page
- Mention academic projects
- Include technical skills clearly

**Common Questions:**
- "Explain the 4 pillars of OOPs"
- "What is normalization? Explain till 3NF"
- "Tell me about your project" (2 min max)
- "Why TCS?" (be specific)

**Red Flags:**
- Low coding score (always submit partial solutions)
- Can't explain own project
- "Only want Bangalore" (flexibility expected)
- Active backlogs (automatic disqualification)

## Quick Prep Priority by Company Type

### For FAANG (Google, Amazon, Meta, Apple, Microsoft):
1. **DSA mastery** — 200+ LeetCode problems, focus on medium-hard
2. **System Design** — 5-6 designs, real-world scale
3. **Behavioral stories** — 8-10 STAR stories, company-specific frameworks
4. **Mock interviews** — 5-6 full loops minimum
5. **Company-specific prep** — LPs (Amazon), Googleyness (Google), Growth Mindset (Microsoft)

### For Service Companies (TCS, Infosys, Wipro, Cognizant):
1. **Aptitude** — Quant, reasoning, verbal (2-3 weeks)
2. **Coding basics** — Arrays, strings, sorting (1-2 weeks)
3. **CS fundamentals** — OOPs, DBMS, SQL (1 week)
4. **Interview prep** — Project explanation, HR questions (1 week)

### For Product Companies (Razorpay, PhonePe, Flipkart):
1. **DSA** — 50-100 LeetCode problems (3-4 weeks)
2. **System Design** — Company-specific (2 weeks)
3. **Domain knowledge** — Payment/fintech/e-commerce (1 week)
4. **Full-stack projects** — Build complete applications (ongoing)

### For Fintech (JPMorgan, Goldman Sachs, Stripe):
1. **DSA** — 50-100 problems (3-4 weeks)
2. **Financial domain** — Markets, trading, compliance (2 weeks)
3. **System Design** — Financial systems (2 weeks)
4. **Quantitative skills** — Math, statistics basics (1 week)

### For Cloud/Infra (Databricks, Snowflake, Cloudflare):
1. **DSA** — 50-100 problems (3-4 weeks)
2. **Domain-specific** — Data/networking/databases (2-3 weeks)
3. **System Design** — Distributed systems (2 weeks)
4. **Open-source contributions** — Build reputation (ongoing)
